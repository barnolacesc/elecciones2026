# Contributing

The project uses the Apache License, Version 2.0, for original project code and documentation. By submitting a contribution, you agree to the contribution terms in section 5 of that license. Do not submit third-party electoral programme files, long excerpts, proprietary assets, or secrets without a documented rights review.

Choose a work package in `openspec/ROADMAP.md`. Read the applicable change proposal, specification, design, and task list. If one is absent, complete and review it before implementation. Keep the pull request focused on one package or a documented dependency. A reviewer checks source fidelity, security, mobile usability, and scope as applicable.

Write code, comments, specifications, and project documentation in English. The public interface is Spanish for the first release. Use concise Conventional Commits, such as `feat(compare): show two party positions` or `docs(method): define source states`. Do not identify an AI model in a commit subject, body, or trailer. Use the actual contributor identity.

Use the pull request template. State why the change is needed and what user-facing or operational outcome it provides. Reference the roadmap package. Do not add an implementation narrative. CI and the OpenSpec task record hold verification evidence.

# Agent working rules

Read `ROADMAP.md`, `openspec/ROADMAP.md`, and the applicable OpenSpec change before work. Take one bounded package such as `E2.3`. Record its identifier in the pull request. Do not treat a proposal-only future change as implementation-ready.

Use English for code, comments, commit subjects, pull requests, and technical documentation. Use clear, controlled technical English; a qualified review is required before any claim of ASD-STE100 compliance. Use Spanish for the public interface and approved public content.

Do not invent political statements, citations, programme status, party relationships, election results, or review marks. Stitch files are visual references only. Do not publish a political claim without an exact, lawful source and human editorial approval.

Work in a branch. Keep each change within its package scope. Do not merge, deploy, or publish without the applicable release gate. Run relevant tests and report results and limits. Do not put secrets, personal political answers, or unreviewed source files in a commit.

Use short Conventional Commits: `type(scope): action`. Types include `feat`, `fix`, `docs`, `test`, `refactor`, `chore`, `perf`, `ci`, and `build`. The subject states the change, not the tool or model used. Do not add AI-model names or model attribution trailers. Preserve the real human or bot Git author identity.

Use the pull request template. Keep the body to a roadmap package, two or three **Why** bullets, two or three **What** bullets, and optional context of at most three short lines. Do not add implementation walkthroughs to the PR body. Keep test evidence in CI and the OpenSpec task record.
